# Token Monitor Duo 使用与开发说明

## 成员与设备

连接同一个 Node Hub 时填写用户名、共享密钥与可选设备名称。用户名清除首尾及重复空白，以 Unicode NFC 规范化，忽略大小写匹配；同名设备归到同一个稳定成员 ID。成员与设备列表从 Hub 动态读取，不限制为两人。

同一人的多台电脑填写相同用户名，设备 ID 各自唯一。客户端只编辑本机资料；更改本机用户名会把本设备重新加入相应成员，其保留历史也随设备归组。用户名是统计标签，持有同一 Hub 密钥的人能查看全部成员数据，没有个人权限隔离。

点击成员展开设备，继续点击设备查看模型。模型可展开分类 Token 与费用。设备明细显示系统、客户端版本、采集时间和同步时间；旧客户端未提供的模型或分类明细显示为尚未上传。

## 额度周期与重置卡

Hub 采用有效的 Codex Pro 主周额度窗口并固定共享账号标识；同一账号可以由另一台设备继续提供读数。其他账号与 Plus 的读数不改变统计边界。客户端只读取本机当前登录信息与额度，不切换或刷新 Codex 登录凭证。

首次已知窗口与正常周期更替依据接口返回的窗口长度和重置时间。所有范围使用 `[start, end)`，结束时刻的记录属于下一轮。这里的「本轮」不是自然周，也不是滚动七天。

重置卡可能提前恢复额度，同时保留原定重置日期，因此不能一律用「结束时间减七天」推断新的开始时刻。自动识别同时观察周额度、重置卡数量与到期信息：

- 接口给出可信的新窗口边界时，按该边界关闭旧周期、开始新周期。
- 周额度下降且有重置卡变化佐证，或得到后续新读数确认后，只能确认重置发生在两次读取之间时，这段区间单独列为「待确认」。前后周期都不包含它。
- 只有短窗口变化、卡片到期、过时读数或被后续纠正的单次百分比下降，不直接创建新周期。
- 后续可靠窗口确定了边界，客户端会用保留的数值账本重新计算相邻周期与模型明细；尚未确认的区间继续独立保留。

额度每分钟读取一次，恢复窗口焦点或手动刷新也会重新读取。新客户端可读取重置卡信息，但不会使用重置卡。旧客户端能否提供这些信息取决于版本和上报内容，缺少重置卡数据时识别能力会减少。服务未运行、客户端离线或接口不提供精确时刻时，无法承诺恢复全部重置历史。

保留最近 104 个已知周期及最多 104 段边界记录。客户端获取 Hub 的周期后本地重新汇总并上传数值。旧设备尚未上传对应周期时显示等待数据，不以零填充。没有有效的新窗口时保留原周期并提示等待。

## 数据来源与费用

macOS 与 Windows 使用原生 Rust 采集器，读取当前 `CODEX_HOME` 的 `sessions`、`archived_sessions`，以及设置中明确添加的日志目录。支持 JSONL 和有解压上限的 `.jsonl.zst`。默认 `CODEX_HOME` 为用户目录下 `.codex`。支持范围为这两个系统的原生日志。

会话累计计数计算为逐次增量，原生与归档副本按会话标识和累计计数去重。根据 `token_count` 记录的时间拆分跨周期会话；输入不含缓存读取，输出包含推理 Token。计数回退、历史前缀截断或累计缺口只保留能确定的增量，并标为不完整。日志时间不能证明请求精确执行时间。

数值账本只保存去重标识、时间、模型和分类计数，已经观察的日志被删除后仍保留。监控开始前已删除的日志无法恢复。首次迁移会重读本机可用日志，原版仅存于汇总缓存而已无原始日志的部分不能精确迁移到额度周期；不能保证新旧累计数完全相同。原版数据和升级前 Hub 备份保留供核对。

默认价格来自随包固定的 [LiteLLM 公开目录](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json)，后台尝试更新本地价格缓存。已知模型按非缓存输入、缓存读取与输出分别估价。未知模型或缺失价格显示未计价 Token；价格变化会重新计算历史估算。API 费用估算与订阅实际扣费、官方额度百分比没有直接换算关系。

本版按设备统计全部读取到的 Codex 日志，不推断账号归属，也不根据共享账号身份过滤历史请求。成员自己管理所用设备和账号。

当天、当月按设备本地日历计算并上报结束时间。离线设备的过期快照不继续计入新日／月，总计及已上传的周期仍可查看。完整状态只表示已读到当前可访问来源，不表示与官方计费完全一致。

## 窗口与后台

采用原版配色、等宽字体和原生玻璃方向。macOS 默认磨砂玻璃；可选系统支持的 Liquid Glass 与 Clear，不支持时回退到磨砂。Windows 使用原生 Acrylic。材质在两个系统上依各自窗口合成器呈现，无法保证逐像素一致。

主界面常驻关闭按钮，点击收起窗口后继续采集与同步；托盘菜单或可选全局快捷键恢复窗口。「退出」才停止后台任务。保留主题、透明度、缩放、置顶、最小化、开机启动、窗口位置与大小。

应用采用独立标识 `com.mrxiuer.tokenmonitor.duo`。数据位于系统本地应用数据目录下同名子目录，包含设置、共享密钥、本机数值 SQLite 账本和 Hub 数值缓存。密钥保存在本机配置中，不返回界面；macOS 文件权限为仅当前用户可读写。Windows 沿用当前用户应用数据目录权限。本地密钥未加密，具有当前系统账户权限的程序可读取。

原始对话、代码、会话标题与 Codex 登录令牌不会上传 Hub。额度请求直接发到 Codex 官方服务，Hub 只收到数值和账号不可逆摘要。同步共享密钥只发往配置的 Hub，重定向不自动跟随。价格更新只下载公开目录。

## 开发与发布

桌面入口为 `desktop/src-tauri/src/lib.rs`，界面为 `desktop/ui/`。Node Hub 继续使用 `src/hub/server.js`。两者通过已有 HTTP/SSE 协议及 [Duo 扩展](API.md#duo-members-and-quota-cycles) 交互。

选择 Tauri 的目的是保留原网页界面和系统玻璃，同时用 Rust 统一采集、SQLite 账本、网络同步和后台任务。使用系统 WebView，避免另带 Electron/Node 运行时。Rust 语言本身不保证整个窗口更省内存；性能评估须连同系统 WebView 进程一起测量。

开发依赖 Node.js 22.15+、Rust stable 与 [Tauri 平台前置依赖](https://v2.tauri.app/start/prerequisites/)。Mac 的基本 app 构建使用 Command Line Tools；Windows 使用 Visual Studio C++ Build Tools、Windows SDK 和 WebView2。常用命令：

```sh
npm ci
npm run verify
npm run desktop:test
cargo fmt --manifest-path desktop/src-tauri/Cargo.toml --check
cargo clippy --manifest-path desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
npm start
npm run desktop:build       # 在 macOS 生成 app
npm run desktop:build:win   # 在 Windows 生成 NSIS
```

GitHub Actions 的 `Duo Build` 在 macOS Apple Silicon 与 Windows x64 执行原生检查和打包。`desktop/src-tauri/Cargo.lock` 固定 Rust 依赖；发布版本须与根 package 和 Tauri 配置一致。安装包运行时无需开发工具。

该分支保留上游 Electron、其他提供方、Worker 和相关测试，方便核对与合并。`npm run start:electron` 为保留的旧入口；定制发布使用 Rust/Tauri 构建。新增桌面依赖集中在 Cargo 清单与 Tauri CLI，价格目录附来源与摘要；不复用上游发行证书。

更新、下载和反馈指向 `mrxiuer/token-monitor`。首版采用手动下载安装，Mac 为 ad-hoc 签名且无 Apple 公证，Windows 无发行签名。安装后先退出旧客户端，避免同一设备被两份应用轮流覆盖。原版保留以便回退。

Node Hub 的数据结构为兼容扩展。部署前备份原数据、环境和服务配置；将新版本放到独立目录，验证后切换入口并保留回退路径。Worker 和 iCloud 不提供 Duo 成员／周期管理服务。
